# Changelog

## Unreleased

- Added a unified `capability.json` format with need/reuse decisions, owner and consumer paths, requirements, native checks and optional SCIP setup.
- Added `inspect`, `review`, `verify` and `refresh-map` commands and read-only MCP contract inspection.
- Added runnable C# and Vue profiles alongside JavaScript, using the shared enforcement engine.
- Replaced the button example's separate orchestration definitions with the unified contract.
- Organized documentation around getting started, adopting a contract and looking up specific integration details.

## 0.10.0 — Qualified responsibility coverage

Added contract-necessity and solution-restraint review guidance. Extended production checks to cover local overrides and component copies that share theme tokens. Compact review format 2 stores one contract digest and rationale with implementation identities. Separate theme and component probes preserve valid wrappers while rejecting bypasses.

## 0.9.0 — Cross-repository adoption

Added distributed adoption guidance and the read-only `inspect-system` command for owners, contract artifacts, dependencies and check references. The command reports inventory gaps; it does not evaluate behavioral conformance or deployment state.

## 0.8.0 — Shared UI contracts

Added the Settings/Team app with a shared button and design tokens. Browser checks cover appearance, loading, disabled state, keyboard access and theme propagation. Production alternatives exercise wrappers, copies and unused-owner references.

## 0.7.0 — Portable two-way enforcement

Added provider/consumer change bindings, review records, stale-binding checks and strict workflow coverage. Production-variant qualification runs the delivery checker against substituted source. The propagation observer compares actual consumer values before and after an owner change.

## 0.6.0 — Two-way change contracts

Added requirements for contract changes to invalidate affected reviews and implementation changes to require reconciliation. Added stale-binding enforcement to the native example.

## 0.5.3 — MIT licensing

Applied the MIT license to code, documentation and distribution metadata.

## 0.5.2 — Local distributions

Added reproducible guidance and source archives, file integrity manifests, local marketplace catalogs and distribution tests. Included catalog examples, dependency locks and installation guidance.

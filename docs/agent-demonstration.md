# Have an agent adopt a contract

Install the [skills/plugin](agent-setup.md), then give the agent a concrete change in an existing application. For a UI change, ask it to preserve loading, disabled and keyboard behavior while meeting the requested appearance.

The agent should inspect existing owners and supported variants, choose reuse or a proportionate extension, identify actual consumers and establish the missing checks. Use native types, schemas and test frameworks before adding a custom adapter. The [shared-button example](../examples/native-stack/README.md) shows the mechanism without requiring a particular application or tool provider.

Require independent behavior and owner-change propagation checks. Challenge the live checker with a correct copy and an unused-owner reference; legitimate wrappers must remain supported. Maintain one compact responsibility review, run normal delivery checks and inspect actual CI results. Fresh review hashes do not turn a failing build into conformance.

Ordinary work needs implementation, relevant tests and contract reconciliation. It needs no transcript archive, experiment report or reset patches. Store research separately outside Git; keep reusable regression fixtures with the product. This walkthrough describes a workflow, not a recorded efficacy result or marketplace-installation certification.
